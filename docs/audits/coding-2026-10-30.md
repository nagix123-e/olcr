# Coding workflow audit — 2026-10-30

## Findings and changes

- **Programming explanation routed to product help.** `テトリスの実装方法を教えて` was intercepted by the bundled OLCR operation guide. Generic implementation questions now retain the normal answer path; operation questions about requests, progress, verification results, or the orchestrator still use the guide. Existing chat-level regression coverage reproduces this boundary.
- **Stop did not interrupt acceptance subprocesses.** Host verification could wait for its full deadline after the task was paused. Verification now checks task cancellation while consuming process output, terminates the owned process group, and reaps it. Cancellation escalates to SIGKILL after a short grace period. Ordinary saved verification commands use the same cancellation path. Read-only source restoration also runs when verification is cancelled.
- **Dependency installation ignored task cancellation.** Package installation now observes the coding generation cancellation scope and reaps its owned subprocess before propagating the pause. Tests substitute a local sleeping Python process for npm; no package registry request is made.
- **Dialog handler cleanup broke valid browser checks.** The verification wrapper previously replaced dialog callbacks without retaining their identity, so `page.off('dialog', originalCallback)` could not remove them. The wrapper now maps callbacks to their wrappers and clears registrations on once/off/removeListener/removeAllListeners. Duplicate pending responders remain classified as a check defect, rather than crashing the runner or requesting source repair.
- **Operation guide regression coverage.** Running the newly added question corpus exposed three topic-selection misses (read aloud, permission settings, sent-message editing). Added natural-language aliases and refreshed the bundled Graphify source hash.

## Validation scope

The audit covers request routing, planning/execution contracts, file changes, verified completion, thinking settings, stop/resume, saved state, task steering, source repair versus check repair, Node execution, Vite/TypeScript build and preview, and real headless Chrome interactions.

Generation and provider results are controlled fixtures. This is not a live external-provider or long-running local-model generation benchmark. Tests use isolated temporary workspaces and databases; the user's current coding task and application were not resumed or restarted.

Test logs are under `/private/tmp/olcr-coding-audit-*.log`. The final backend suite is `/private/tmp/olcr-coding-audit-complete.log`; UI regressions are in `/private/tmp/olcr-coding-audit-ui.log` and TypeScript checks in `/private/tmp/olcr-coding-audit-typecheck.log`.

Final results: backend 446 passed and 5 explicitly obsolete lifecycle tests skipped (451 collected); UI 73 passed; TypeScript and Python/JavaScript syntax checks passed. No failing tests remained in these suites.
