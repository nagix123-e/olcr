# 作業フォルダの添付

チャットの「＋ → 作業フォルダを添付」から選択するか、入力欄にフォルダをドロップする。フォルダを一個の通常ファイルとして読み込まず、配下のファイルを参照・編集できる会話の作業対象として登録する。

- デスクトップでは、選択した元のフォルダを直接使用する。
- ブラウザーでは相対パスとバイト列を取り込み、アプリのデータディレクトリ配下のコピーを使用する。ブラウザーから選択元へ直接は書き戻さない。
- プロジェクトの`workspace_path`、全体の許可ルート、ワークツリー設定を変更しない。プロジェクトの作業場所が未設定でも添付フォルダで作業できる。
- 会話ごとに作業対象を分離する。通常チャット、続きのストリーミング、Coding Taskに適用する。作成済みTaskはフォルダIDを固定し、その後別のフォルダを添付しても作業対象を変えない。
- 入力欄に作業フォルダ名を表示し、×で今後の依頼から解除できる。実行中Taskは元の対象を維持する。

最大2000ファイル。ブラウザー取り込みは合計50 MBまで。`.git`、`node_modules`、`.venv`、`__pycache__`などの生成物は取り込み・一覧対象外。外側を指すシンボリックリンクや`../`による範囲外パスを作業ファイルとして取り込まない。既存のファイル操作時の権限確認は引き続き適用する。

会話へ登録する際に、DBへフォルダの所有会話とルートを保存する。プロンプトには範囲を絞ったファイル一覧・テキスト抜粋を未信頼データとして渡す。元ファイル中のタグをSkill指示として取り出さない。資料選択・圧縮でもファイル一覧のJSONを壊さない。

- `chatAttachments.test.ts` / `ComposerActions.test.tsx` / `ChatComposer.test.tsx`: フォルダ内の階層・空ファイル、複数バッチの列挙、添付メニュー、作業フォルダの表示と解除。
- Rust `read_dropped_folder_preserves_directory_as_working_files`: ネイティブ側で複数ファイル入りのフォルダを受け付ける。
