## Cross-case findings

1. **Conversation separation was deliberately not used.** The 50 turns were run in one chat to expose contamination. Later source inspection found direct explanations for cases 05 (country substring collision), 27 (unbounded early-record sampling), 31 (default airport), and 02 (year-only sorting). History leakage remains a risk to guard against; these observations do not establish it as the cause. See the repair record below for the corrected diagnosis.
2. **The dominant functional defect is single-provider planning.** In most turns the catalog found several candidates, but `AUTONOMOUS_ANALYSIS_BRAIN_PLAN` reported `PLANNED_COUNT=1`. Only a few requests produced multiple successful API calls, and even then composition frequently omitted one returned source.
3. **HTTP success is often semantically empty or wrong.** Examples include Japan-only OECD unemployment for Southeast Asia, Albania HICP for EU, crude-oil stocks for electricity mix, Afghanistan GDP growth for humanitarian SDGs, and 1950s UNHCR data for Latin America.
4. **Provider/candidate disagreement and abstention are recurring.** `LAYA_EMBEDDING_CONFLICT`, confidence floors, and `ROUTER_SELECTED_TOOL=NO` repeatedly suppress useful routes; generic web fallback then returns pages rather than the requested joined indicators.
5. **Argument compilation and defaults are unsafe for broad requests.** Malformed locations (case 14), arbitrary country/time (cases 27, 35), and default airport/station selection (cases 17, 31) should be replaced with request-grounded arguments or an explicit clarification. Never silently present a default as the requested region.
6. **Evidence ownership/composition needs stronger checks.** Compare answer claims to the current turn’s evidence and reject old-turn facts, unrelated geography, mismatched units/indicators, stale years, and API records not surfaced in the GUI. Preserve per-turn request IDs through planner, adapter, evidence bundle, and synthesis.
7. **Fallback quality is uneven.** Search fallback can keep the UI responsive, but it often substitutes explanatory pages for numeric structured data. The answer must clearly label this as a fallback and avoid presenting it as the requested API analysis.
