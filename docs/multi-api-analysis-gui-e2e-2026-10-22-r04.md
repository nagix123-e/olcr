## 修正内容と契約テスト

r04の結果では、同一会話の履歴混入より、プロバイダーが示す能力制約・部分応答の扱いと、返却内容の課題適合性検査が主因候補だった。修正では、コンパイラが `unsupported_capability` と示した呼出しを実行しないこと、`request_complete=false` や不足フィールドのある応答を必要証拠の充足として数えないことを実装した。正常な完全応答は従来どおり証拠に残し、不足分だけをフォールバック対象にする。

当初の修正直後の対象契約テストは22件成功。r05の途中で見つかった共通原因にも追加修正を入れ、対象回帰テスト435件（428成功、7スキップ）で確認した。追加修正後のGUI全50件は実施しておらず、GUI合格として扱わない。
