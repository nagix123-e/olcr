# 2026-10-12

## macOS Speech as an alternate voice input engine

- Added a localized voice-input selector to Settings: LFM local model (default) or macOS Speech on-device. Store the selection in `olcr-speech-engine` and update the active composer without a restart.
- Keep the existing microphone capture and phrase-by-phrase composer flow. Route each audio segment to either the LFM streaming endpoint or a small signed macOS Speech helper, forwarding partial transcription back into the composer.
- Build the helper from `macos-speech-helper.swift` with the macOS Speech framework and bundle it as `Contents/Resources/speech/olcr-macos-speech`. The helper selects `ja-JP` or `en-US`, requests Speech authorization, requires `supportsOnDeviceRecognition` and `requiresOnDeviceRecognition`, and returns localized error codes when the Mac/language cannot recognize offline. No server fallback is enabled.
- The Tauri command bounds and validates the PCM WAV payload, writes it to a mode-0600 temporary file which is deleted after recognition, relays partial text events scoped to a random session ID, and removes temporary audio on completion/error.
- Add `NSSpeechRecognitionUsageDescription`. Settings explains the Apple Speech permission and on-device support requirement. Frontend production build, Rust `cargo check`, Swift helper compile, app packaging and deep codesign verification succeeded. The packaged helper is an arm64 Mach-O executable.
- No actual speech recognition request was run because the first Speech authorization call can change system privacy state and show a system prompt. No GUI interaction was performed because an OLCR app was already running and the repository `AGENTS.md` forbids launching alongside it or terminating it. Restart from the rebuilt signed bundle to grant Speech access and try the native option. If that Mac or locale does not support offline recognition, use LFM.
