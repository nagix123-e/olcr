# Convert: opt-in managed runtime

- Default: `convert_enabled=false`, persisted through the existing capability settings API.
- Existing Settings → Chat capabilities UI contains the Convert switch, setup status and Retry.
- Opening Settings, starting OLCR or requesting a conversion while OFF does not fetch tools.
- Explicit ON starts asynchronous installation; OFF cancels setup and stops the private VM.
- Docker and Homebrew are not prerequisites. The backend acquires checksum-pinned Lima
  2.0.3 and Ubuntu 24.04 (20261017), then digest-pinned ConvertX v0.19.0 in a private VM.
- Cache survives OFF/restart. The owned container is restarted without a registry pull.
- No host directory mounts; only the conversion TCP port is forwarded to loopback.
- Guest UID is 1000: inheriting the macOS UID 501 caused Ubuntu logind/rootless
  containerd setup to hang in the first real-machine probe.
- nerdctl image inspection by multi-platform digest did not find the cached image after
  reboot. Reusing the existing owned container resolves this without an online pull.
- File bytes remain unchanged before conversion; project workspace or `~/Downloads`
  receives output. Existing filenames receive numeric suffixes. Common upstream format
  aliases (jpeg/jpg, markdown/md, latex/tex) preserve the requested output extension.

package/release staging; external runtime assets are fetched only after opt-in.
