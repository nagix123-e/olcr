# `/skill` executes the selected Skill

`/skill name` previously returned an installation/registration JSON object. It now executes the selected Skill, using the current conversation and workspace as bounded background. `/skill name request` preserves the supplied request and returns the work result or answer. Missing task inputs are handled by the Skill-guided answer rather than a registry dump.

The command inherits its conversation's project when the caller omits `project_id`. It resolves the conversation's coding workspace or attached folder before falling back to the project workspace. Projectless conversations stay projectless. The context contains the selected Skill's instructions and base directory, recent conversation background, and a bounded preview of actual workspace files. Secret paths, generated directories, symlinks and binary files are excluded from that preview; source contents remain data. Context compaction preserves the Skill envelope and valid background JSON.

Both `/api/chat` and `/api/chat/stream` recognize explicit Skill commands before generic assistant-action, conversion and custom-agent routing. They share `/api/commands` execution and persistence, so a request produces one user/assistant pair. A bare invocation suppresses the generic automatic Web lookup; explicit requests retain their normal execution routing. The selected primary Skill remains pinned, and existing unavailable/disabled Skill errors remain in place. The composer shows each Skill's description instead of its registration status.

Validation uses disposable app-support/DB profiles, without touching the user's database or running app. Focused coverage includes bare and prompted commands, inferred project scope, attached projectless folders, both chat transports, native installed Skills, unavailable Skills, bounded source context, Skill delimiter handling, actual generation and actual workspace file writes. The composer tests and frontend production build pass. The full frontend suite also exposes one failure in the unchanged screen-capture diagnostic-text expectation (`ScreenCapture.test.tsx`); the focused screen-capture rerun reproduces it.

The focused backend run passes all 34 tests; the composer passes all 49 tests (83 related tests total). The debug macOS bundle is rebuilt with build ID `olcr-explicit-skill-execution-20261028`. A running user app is not terminated or relaunched by this change.
