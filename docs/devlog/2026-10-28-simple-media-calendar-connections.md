# Simpler YouTube and calendar connections

YouTube search now reads bounded public search metadata and plays through the existing official YouTube player. It needs no API key, developer account, search-provider key, cookies or media downloader. Legacy key arguments are accepted for compatibility but not sent. Valid direct video URLs still skip search. When public search is unavailable, the chat offers the official YouTube search page instead of asking the user to provision credentials. External Access continues to control YouTube network use.

The default calendar integration is the Mac's native Calendar store through EventKit. Settings provides one Connect Calendar action, which requests macOS calendar permission through a bundled signed Swift helper. There is no Google developer-console/client-ID/secret flow in the normal Settings UI. Calendar selection and time zone are in a secondary disclosure; the Mac default calendar and device time zone work without extra configuration. Calendar and macOS privacy-settings buttons handle missing calendars and denied permissions. Local calendar actions do not require External Access.

The native helper uses full event access on macOS 14+ and the compatible authorization API on macOS 13. Calendar usage descriptions are embedded in the helper and app. It lists calendars and events, validates write targets and etags, and applies changes to a single recurrence occurrence. Existing chat previews and confirmation/idempotency controls remain in place. Pending actions record their provider, preventing an old Google preview from being applied to the native calendar. Switching from old Google preferences starts with the Mac default rather than reusing an incompatible Google calendar ID.

The app passes the bundled helper path to its owned backend. The build compiles and signs the helper automatically and includes it in app resources. Authorization is provided by macOS; the user must approve the initial OS prompt. The implementation does not bypass that prompt or embed account secrets. Calendars already available to the Mac Calendar app are accessed through the store.

Validation uses temporary databases and synthetic calendar events, with no modification of the user's real calendar. Native backend tests cover one-step connection, permission denial, native queries with external access disabled, confirmed writes, duplicate confirmation and provider ownership. The real Swift helper compiles, passes its date-format self-test, and reports permission status without requesting authorization. Frontend tests cover key-free UI, connect/default preferences and immediate denial recovery. A live public YouTube metadata search returned five valid candidates without a key; failure handling is tested separately. Native authorization and real-calendar CRUD await the user's first in-app connection, rather than attributing a CLI permission grant to the wrong process.

EventKit references: [Apple: accessing the event store](https://developer.apple.com/documentation/eventkit/accessing-the-event-store), [requestFullAccessToEvents](https://developer.apple.com/documentation/eventkit/ekeventstore/requestfullaccesstoevents(completion:)).
