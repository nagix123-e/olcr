## P9 OpenCV/APC telemetry extension

A Graphify-backed source-path review favored extending the existing `PerceptionController` snapshot and `ScreenCaptureManager` status/frame notices, rather than adding another scheduler, telemetry store, or per-frame journal. APC now reports separate saturating counts for known event wakeups (AX/action/scroll/effect/track-start signals) and pixel-derived `pixel_change`/`scene_change` wakeups; stable frames do not increment either counter. These are policy signal counts, not operating-system wakeups, and remain advisory policy metadata. The frontend deduplicates by policy revision plus counter values, persists policy revision changes immediately, and coalesces same-revision counter-only changes to at most one advisory World State update per second.

With `opencv-perception`, capture notices and status expose a saturating per-session cumulative timer covering the existing `estimate_change` change/scene/ROI call and grounded `OpenCvFlowTracker::update` intervals. The UI labels it as cumulative OpenCV processing. It excludes frame arrival/acquisition, pixel-buffer access and BGRA→RGB conversion, IPC/UI, OCR/VLM calls, OS CPU use, and OS-dropped frames; the feature-off Rust image fallback reports zero for this OpenCV-only metric. Existing rolling p50/p95 detector and LK update timings remain separate measures.

Validation: native full tests passed 72/72 feature-off and 76/76 with `opencv-perception`; the OpenCV run used Xcode Swift 5.5 fallback, the six-module `OPENCV_LINK_LIBS` set, and controlled GUI-test compile-time environment. Focused frontend telemetry tests passed 5/5, TypeScript typecheck and production build passed (749.44 kB JS / 224.66 kB gzip, existing chunk warning), the GUI-authenticated advisory World State regression passed 1/1, and `cargo fmt --check` passed. No live capture or TCC interaction was performed, so V7 remains PARTIAL: no achieved FPS, OS-drop, end-to-end system-cost, or task-success measurement is claimed.
