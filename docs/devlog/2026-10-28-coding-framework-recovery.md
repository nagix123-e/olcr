# Multi-file framework coding recovery

The reported meal-planner task created its ten initial files successfully.
Its plan carried prose install/build criteria without executable contracts.
The dependency-free static acceptance normalizer excluded TypeScript/Vite, so
the scheduler repeatedly called Implementer instead of executing those checks.
A later proposal contained an invented `catch (err)` preimage for a function
whose actual source already contained `catch {`. The batch was rolled back.
The final retry contained only identical replacements and exhausted recovery.

## Changes

- Extend the owned acceptance schedule to manifest-backed Vite JS/TS/React
  projects. Retain file ownership and dependencies, defer integration checks
  until all implementation inputs exist, and preserve every behavioral criterion
  in final acceptance. Explicit executors and failure checkpoints retain their
  existing schedule.
- Prepare dependencies in a task-owned verification cache using the existing
  validated package executor. Install scripts remain disabled. Build a fresh
  disposable source copy using the actual TypeScript and Vite CLI entry points;
  serve its compiled output to Chromium. The user's source tree and dependency
  files are not modified by verification. Criteria text never becomes shell code.
- Supply measured install/build evidence to mechanical checks. Run Vitest when
  the project declares it, requiring registered tests and reporting failures.
  Compile TS modules with Vite for module-level assertions, preserving imports.
  Compiler errors are application failures; runtime/install availability errors
  remain executor failures.
- Replace the managed snapshot's eight-file cutoff with a bounded byte budget.
  Patch-preimage failures can select source-bound line edits even before a test
  failure exists; source hashes, scope guards, structural checks and rollback
  still apply.
- Retain completed artifact work across an idempotent retry only for the exact
  host artifact/readback gate, with actual prior mutations and current matching
  post-write hashes. Rolled-back, unowned, missing and externally changed files
  cannot satisfy this exception. Behavioral completion still requires final
  executable acceptance.

## Validation

- Real isolated React/TypeScript/Vite build and Chromium button interaction.
- Actual TS module loading with a relative import, actual Vitest success and
  intentional assertion failure, and an intentional TypeScript compiler error.
- Regression coverage for twelve authorized source files and patch recovery
  without a prior test result.
- Read-only replay of the reported task's stored plan and reports: its retained
  P1 artifacts satisfy the corrected artifact gate; install/build remain in the
  final acceptance gate. This is not a claim that the unfinished app is complete.
- Related regression suite: 271 cases, 266 passed and five existing skips.

No external model calls or live OLCR GUI acceptance run were performed.
Test DB/settings profiles are temporary; existing Node/Chromium components are
read as installed resources. Running OLCR backend processes must be restarted
to import these Python changes. The user's persisted task and generated source
files were not rewritten by the read-only replay.
