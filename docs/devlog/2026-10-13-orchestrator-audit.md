# Coding Orchestrator 不具合監査・修正記録（2026-10-13）

対象はローカルの計画作成、チャット操作、工程実行、検証、再計画、再開、停止ログ、進捗表示、完了判定。既存のGraphifyグラフで関連関数とテストをたどり、現行ソースと回帰テストで確認した。クラウドTaskは対象外。

## 修正した問題

| 問題・発生条件 | 修正 |
| --- | --- |
| 無効な再計画からの再試行でも、保存済み `REPLAN_REQUIRED` 判定が優先され計画モデルへ戻る | 現在の工程IDと計画改訂に結び付けた一回分の実行許可で、当該判定を越えて工程を直接再実行。許可は実行結果を取得して消費する |
| 再開を連打すると古い入力待ち状態から重複して復旧回数を予約し、実行状態を書き換え得る | 再開操作を直列化してDBから状態を再取得。既に待機・実行中なら二重予約しない |
| 直接再試行中にモデル接続が中断すると、その後の再開が再計画へ戻り得る | 実行結果を取得するまでは実行許可を保持。中断後も同じ工程の再実行経路を維持する |
| 新しい決定的な工程評価には、次の実装モデルへ渡す未達条件の診断がない | 未達Done/Verifyと実際のエラー・検証失敗を診断へ保存し、再実行と再計画へ渡す |
| 一般的な工程名だけが実装モデルへ渡り、元の細かい仕様が落ちる | 元のユーザー要求を最大8,000文字で工程契約へ同梱。切り詰めの有無も明示する |

| 正常に実行された単体テストが、未要求のビルド `NOT_RUN` によって未達になる | 単体テストと要求されたビルドの証拠を区別する |
| 型チェックの実行記録だけで最終受け入れを通過する／無効なno-opのハッシュ証拠を一般的Doneが覆す | 型チェックには成功記録を要求し、無効な明示no-op候補を合格へ昇格しない |

## 検証

- 12モジュールのバックエンド回帰テストを隔離DBで実行。既存の計画・スコープ承認・停止・再開・完了・実際のtyped executorのテストと、今回の実行境界の回帰テストを含む。
- テスト内では同じローカル判定モデルの初期化を再利用し、各fixtureによる無関係なモデル再ロードを省いた。製品の初期化動作は変更していない。
- 実際の同梱Node.jsで `node:test` の成功と失敗を実行し、結果の記録を確認。
- UIの進捗・入力・差分表示のテストと、TypeScript/Viteビルドを実行。
- 旧仕様を期待していたテストは、計画中に返信しない仕様と、ユーザーが明示した工程境界で停止する仕様に合わせた。古いGemma管理経路を前提とする既存スキップは維持。

## 残る確認範囲

- 今回のテストは制御経路・証拠判定の回帰確認。実際のローカル生成モデルが昼食ルーレットの全仕様を満たすまで作れるかは、この版のGUIで改めて実行する必要がある。
- 8,000文字を超える要求は工程契約では先頭部分だけを送る。長い要求の後半にある細かい仕様は、Plannerが対応工程のDone/Verifyへ保持する必要がある。
- 検証対象の復元は指定されたファイルに対して行う。任意の検証スクリプトをOSの隔離環境で実行する仕組みではない。指定対象外への副作用を全面的に防止する保証はしていない。
- Nodeの実行結果はテスト成功・失敗の証拠になるが、終了コードやテスト件数だけでは、ユーザー要求の全機能をテストしていることを保証できない。元の仕様の保持と検証範囲の確認は引き続き必要。
- 実行中のアプリの再起動や、利用者の既存Taskの履歴・上限の書き換えは行っていない。
