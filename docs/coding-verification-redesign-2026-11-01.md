# コーディング検証・修復経路の修正

添付ログの停止Taskを調査。実装2工程は完了しており、最後の保存・復元の受け入れ検証コードが、予算入力を行わず自動作成を実行していた。修復用プロンプトには失敗コード本体がなく、観測入力も先頭2件に切り詰められていた。さらにオフライン検証が意図的に遮断する外部フォントのconsoleエラーをアプリ本体の失敗と同一扱いにしていた。

## 変更

- 修復対象の条件IDと一致する失敗チェック本体を、実行証拠として次の修復呼び出しへ渡す。レビューのソース引用・予算など後方の入力欄も保持。条件IDの順序が異なる応答にも対応。
- 既存の独立した意味レビュー・実ブラウザー再実行・合格チェックの保存を維持し、断言を弱めて合格させない。
- ブラウザーが意図的に遮断した外部リソースの読み込み失敗だけを最大20件の警告へ分離。アプリ自身のconsoleエラー、JavaScript例外、外部通信禁止要件の違反は引き続き不合格。
- 同じモデル呼び出し・処理段階の進捗は最新値へ更新し、開始・失敗・切替・受信した思考ログを毎秒の進捗で押し出さない。既存の大量ログも表示時に圧縮。欠測トークン数はnull表示せず受信文字数を表示。待機秒数は最新の更新時刻から算出。

## 検証

- ユーザーの実ファイルと保存済みDONE:1チェックを/tmpに複製。未修正チェックは失敗。予算入力だけを追加したチェックは、元の全断言を保持したまま合格。複製側の保存データ読込を壊すと同じチェックが失敗。元の実装・ユーザーDBは変更していない。
- 実Chromiumで外部スタイル遮断を含むローカル操作が合格し、アプリ自身のconsoleエラーは失敗することを確認。
- 1100件の進捗でも開始・受信思考を保持。古い500件のnull進捗も1件へ集約。
- コーディング関連304件、299成功・5件既存skip。修復・ログ・実ブラウザー関連46件、画面32件が成功。TypeScript/production build成功。
- フロント全体443件中438成功。変更範囲外の地図3件・ModelsPanel1件・ScreenCapture1件は前回と同じ失敗。
- 独立レビューの時刻・ソース引用の受け渡し・条件IDとの対応の指摘を修正。

元の献立アプリTask全体をモデルで再実行して完了にする操作は行っていない。今回の実データ再現は保存・復元の失敗チェックを対象とし、アプリの全要件達成を主張しない。
