# 50課題の実GUI E2Eから抽出した共通不具合の修正

## 対象と結論

対象は [同一会話で実施した50課題のGUI記録](multi-api-analysis-gui-e2e-2026-10-21-r02.md)。43–50、1–42の順序と、会話を分けない条件は当該記録のとおり。

課題ごとの完成回答やAPIの組み合わせを本番コードに登録する方式は採っていない。現在の依頼文から独立した証拠要件を取り出し、候補選択・実行計画・引数・返却レコード・回答の各段階で要件を落とさないようにした。

修正後のオフライン回帰検証は **411テスト中404成功、7スキップ、失敗・エラー0**。公開APIの実通信はWorld Bank、UNHCR、ClinicalTrials.gov、IMFの4アダプターで確認した。**修正後の50件の実GUI E2Eは未実施**であり、この記録は50件の合格を意味しない。

## 原因の訂正

同一会話で異なる対象の情報が現れたことと、履歴を原因とすることは区別する。

- 課題02：BLSの年・月を年だけに縮めて整列していたため、同じ2026年の古い月が最新値になり得た。月を保持する回帰テストで再現し、修正した。
- 課題05：国名抽出が「ラテンアメリカ」中の「アメリカ」を米国として抽出していた。文字列の境界と地域名を処理し、米ドル表記・ISOコードとの衝突も防いだ。
- 課題27：UCDPに期間を付けず先頭ページの少数記録を使うと、古い国・年が質問の対象のように表示される。期間・件数を限定し、部分サンプルであることを表示する。
- 課題31：空港未指定時のRJTT既定値が原因だった。空港・ICAOの指定を求める。

これらを履歴混入の確証とは扱わない。同時に、回答の数値・国名を今回の証拠パケットと照合し、過去の数値などを引用だけで正当化させない保護も追加した。

## 実装箇所

- `backend/olcr_api/analysis_coverage.py`：依頼からの証拠要件、必要API、未取得指標の検査。
- `backend/olcr_api/analysis_scope.py`：国/地域と期間、観測レコードの照合。
- `backend/olcr_api/app.py`：候補・計画の要件保持、入力確認、部分成功の補完、証拠の展開・合成・表示、依頼単位のID。
- `backend/olcr_api/external_tools.py`：既存アダプターの引数・応答正規化・欠測/期間/単位メタデータ。
- `backend/tests/test_analysis_pipeline_contract.py`：今回追加した共通契約の回帰テスト。

APIの別名は既存のcanonical aliasを使う。モデル生成は既存の`_generate_brain`、補完は既存の`runtime.execute`へ渡し、今回の修正で別のモデルフォールバック順序を設けていない。

## 確認の限界

- 修正後のソースを使う50件の実GUI E2E、同一会話での実モデル合成品質は未検証。
- 既存アダプターが必要な粒度・指標に対応していない課題は、追加確認・不足表示・補完へ進む。これを、当該APIで完全なデータ結合が実装されたこととは扱わない。
- 国/年メタデータが存在しない記録は照合不能であり、対象一致を証明したことにはならない。推計・サンプル・欠測から因果結論は作らない。
- 数値/国名の照合は防御策であり、すべての自然言語の主張が意味的に正しいことを証明するものではない。
- 上流APIの認証・停止・タイムアウト・空応答は引き続き起こり得る。実通信4系統の成功を、全APIの稼働保証には拡張しない。
