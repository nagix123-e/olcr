# 旅行計画

チャットで「京都への旅行計画を立てて」または `/trip` と送ると旅行条件を聞き取ります。条件は会話単位で保存され、再起動後も同じ会話から続けられます。

自然文で条件を伝えるか、次の形式で入力できます。ラベル形式では条件の読み取りにモデルを使いません。日別旅程の作成には設定済みの通常会話モデルを使います。

```text
旅行計画を立てて
出発地：東京
目的地：京都
開始日：2026-12-01
終了日：2026-12-03
人数：2
予算：全員で10万円（交通・宿泊込み）
興味：庭園と美術館
希望：徒歩移動を少なめに
ペース：ゆっくり
```

出発地・目的地・開始日・終了日・人数・予算が必要です。予算には通貨と1人分か全員分かを含めてください。最大31日、1〜100人を受け付けます。

- 「旅程を修正して。2日目はゆっくり」：条件を保持して再作成します。
- 「旅程を修正して」に続けてラベル形式で入力：指定項目を更新します。
- 「旅程を見せて」または `/trip show`：保存済みの案を再表示します。
- 「旅程を再作成して」または `/trip plan`：保存条件で再試行します。
- `/trip new`：同じ会話で新しい旅行条件に切り替えます。
- 「旅程を中止」または `/trip cancel`：条件の聞き取りを終了します。以前の案は再表示できます。

外部アクセスとWeb検索が有効なら、設定した検索プロバイダーで観光・交通情報を検索し、最大4件のページ本文を読みます。検索語には出発地、目的地、興味が含まれます。出典URLと取得時刻を表示します。出発日が短期予報の対象なら開始日の天気も取得します。Web検索が無効・失敗の場合も未確認箇所を明示して案を作成できます。

旅程・条件・再送処理の記録は既存プロフィールのSQLite内に保存します。会話のメッセージを編集して巻き戻した場合、取り消した旅程の条件は次の計画に引き継ぎません。会話にカスタムエージェントが設定されている場合は、そのエージェントの既存動作を優先します。

料金・移動時間・空室・空席は、根拠のある最新情報がない限り未確認です。旅程案だけでは予約されません。

## チャットから予約を進める

先に旅程を作成し、「ホテルを予約して」「新幹線を予約したい」「京都で夕食の店を予約したい」「レンタカーを予約して」のように依頼します。予約カテゴリが曖昧なら、交通・宿泊・食事・体験・レンタカーのどれかを尋ねます。食事は希望日と時刻、レンタカーは受取・返却日時を確認します。検索結果が複数なら、チャットの候補カードから選びます。

この版で予約先に接続する方法は、OLCRの永続ブラウザープロファイルです。外部アクセスを許可し、対象サービスへログインした状態で、OLCRブラウザーに予約検索画面または条件が表示された画面を開いてください。対象サイトが公開HTTPSで、画面に日付・人数・税込合計・取消条件を確認でき、検索や予約確定ボタンを一意に判別できるときだけ進みます。ログイン、本人確認、支払情報、OTPの入力が必要な場面はブラウザーに戻して本人に操作を依頼します。認証情報や決済情報はOLCRのモデル入力・予約記録へ渡しません。

候補を選んだ後、チャットには最新の合計金額と追加料金の内訳、日程・時刻、人数、取消条件、有効期限を含む確認カードを表示します。予約ページに追加料金の内訳が見つからないときは「未内訳」と表示し、0円とは扱いません。カードの「この内容で予約する」または「この内容で予約して」という明示的な確認が来るまでは確定操作をしません。期限切れ、金額や条件の変更、複数の確定ボタン、本人確認・決済画面では確定を止めます。予約先の成功応答を読み取れたときだけ「予約先が確定」と表示します。結果が不明なときは自動再送せず、予約サイトで重複の有無を確認してください。

この実装には、交通会社・ホテル予約サイト・飲食店・体験サービスの公式APIアダプターはまだ含まれていません。プロバイダー登録口は用意し、公式に利用できるAPIがあるサービスは今後追加できます。現在はログイン済みブラウザーで確認できる範囲に限られ、すべてのサイトで自動検索・予約できるわけではありません。対応条件を満たさないサイトは、予約サイト上での手動操作へ引き継ぎます。

予約の確定後、旅行カレンダーへの登録や価格監視はまだ行いません。
