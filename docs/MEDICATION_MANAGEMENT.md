# 服薬管理

通常チャットで利用できます。頭痛薬に限定せず、薬名・規格・1回量・単位・用法を確認して薬を登録します。同名でも規格や用法が異なる場合は別の薬IDになり、曖昧な薬名で服用実績を追加しません。処方された内容をAIが補完・変更する機能ではありません。

## 1. 処方箋・説明の登録

処方箋や薬袋の画像を添付して「この処方箋を服薬管理に登録して」と送ります。デスクトップのローカルOCRで文字を読み取り、未確認の案として表示します。判読できない箇所は文章で訂正してください。画像中の見出しや用法が認識できない場合も、自動で用量や時刻を決めません。複数の薬は1種類ずつ確認します。画像内の氏名などは薬の項目として登録しませんが、確認用OCR文字と通常の会話履歴には含まれ得るため、不要な個人情報は添付前に隠してください。

文章の場合の例（架空の薬。実際の処方内容を入力）：

```text
服薬を登録
薬名：処方薬A
規格：5mg
1回量：1錠
用法：朝夕1回ずつ各1錠
成分：薬剤師の説明で確認した成分名
24時間上限：2錠
最小間隔：6時間
```

薬名・規格・1回量・用法は必須です。成分、24時間上限、最小間隔は処方・説明で確認できた場合だけ入力します。全て照合して「服薬を確定」と返信すると保存します。訂正は「規格：10mg」のように項目名付きで送れます。「キャンセル」で案を破棄できます。

## 2. 服用実績と履歴

```text
今、処方薬Aを1錠飲んだ
2026-11-07T08:00+09:00 処方薬Aを1錠飲んだ
服薬履歴を見せて
登録した薬を見せて
服用記録を取り消し 記録ID
服用記録を訂正 記録ID 2 2026-11-07T08:00+09:00
```

訂正コマンドの数値はその記録の登録単位で扱います。異なる規格・用法が複数ある薬は、薬名の代わりに一覧の薬IDを使ってください。量・単位が不明な報告では記録しません。日時指定なしで現在時刻を使うのは「今」と明示した報告のみです。未来の服用は実績にできません。

同一の送信IDの再配信を重複記録しません。メッセージの編集・再送で会話を巻き戻しても、実績と外部予定は保持し、再送時には追加せず訂正へ案内します。会話削除も服薬台帳の削除を意味しません。

集計は本人のローカルプロファイル内に保存した服用実績について、当日を含む直近30暦日を対象に行います。回数、使用日数、量を薬ごとに表示し、カレンダーの予定は服用済みと数えません。記録漏れや未登録の併用薬を把握することはできません。

## 3. 服用予定

薬を登録後、次のように依頼します。

```text
服用予定を作成
薬名：処方薬A
開始：2030-01-01
終了：2030-01-30
時刻：08:00,20:00
接続先：Apple
通知：5分
薬名を予定に表示：いいえ
```

日付は実際の開始・終了日に変更してください。頓服は定期予定にしません。開始・終了日と具体的時刻は必須で、食後などの説明から時刻を勝手に設定しません。タイムゾーンはチャットを送信した端末の設定を使います。期間・件数・接続先・通知・薬名公開の案を確認して「服用予定を確定」で登録します。

Appleはサービス接続のカレンダーカテゴリとmacOSの許可が必要です。Googleを指定する場合はサービス接続でGoogleカレンダーを有効にし、「カレンダーへの登録を許可」から追加認証してください。Googleは本人所有の既存カレンダーに対する `calendar.events.owned` を使い、既存の読み取り認証・Keychain保存経路を共用します。

一度に最大20件ずつ確定処理します。残りがある場合は「服用予定を確定」で続けられます。1つの案は最大366日・500件で、それ以上は期間を分けて確認します。通信失敗で登録結果が不明な予定は照合し、未確認のまま新規作成を繰り返しません。不明な結果が残る場合は実カレンダーも確認してください。

```text
服用予定一覧
服用予定を再開 予定ID
服用予定を停止 予定ID
```

再開は続けて「服用予定を確定」で照合と残りの登録を行います。案をキャンセルすると未登録分を取り消し、完了・不明の予定は保持します。停止は「服用予定の停止を確定」で実行します。OLCRが作成した将来の予定のみを対象とし、外部で変更された予定は削除せず知らせます。既存予定を変更する場合は将来分を停止し、訂正した条件で改めて登録します。服用実績は保持します。予定は登録元の会話で管理できます。

通知はOS・カレンダー提供元の設定に依存します。既定の予定名は「服用予定」で、薬名を入れる場合は提供元・共有相手・通知画面に表示され得るため確認が必要です。OLCR終了中の独自の過量警告は配信せず、服用リマインダーをカレンダーに担当させます。

## 注意表示の範囲

全ての薬について、原本と照合して保存した1回量・24時間上限・最小間隔と実績を比較します。成分が確認できる場合は、同成分として登録された別製品の直近24時間の併用も知らせます。単位を自動換算したり、未登録の成分まで推定したりしません。上限不明の薬について、回数だけで過量か安全かを判定しません。

頭痛時の使用日数の注意は追加の限定的な基準です。「用途：頭痛時」と、確認済み成分を登録した場合のみ有効です。初期分類表はアセトアミノフェン／パラセタモール・アスピリンとスマトリプタンを対象にし、商品名から成分を推測しません。非オピオイド鎮痛薬群は使用日の和集合で15日、トリプタン群は10日を直近30日の注意の目安とし、対応する複数分類の併用も考慮します。この分類表にない成分・配合剤は月間基準の判定対象外です。一般の薬に頭痛薬の基準を適用しません。

1か月の記録だけで薬剤使用過多頭痛と診断したり、薬の中止・減量を指示したりしません。使用頻度への注意は医師・薬剤師への相談を促すものです。処方上限・間隔に関する注意は服用記録・履歴表示時に出します。過量服用の可能性や体調異常があるときは月間集計を待たず医療機関へ相談してください。

## 保存・削除

薬と実績はプロジェクトに依存しない本人のローカル台帳です。モデルや症状評価APIに自動挿入しません。「服薬データを全削除」→「服薬データの全削除を確定」で台帳を消せます。通常の会話履歴と外部カレンダー予定は別に削除します。薬ごとの単位・用法を変更する場合は新しい処方として登録し、過去の実績を書き換えません。

## 検証

合成の薬情報と隔離DB・模擬カレンダーで検証します。実処方画像の臨床評価、実アカウントへのカレンダー登録・通知配送、macOS権限画面での確認は別途必要です。
