# 外部モデルの利用量とリクエスト数

トークン数が欠けた応答を記録から落としていたため、利用済みでも0 tokensに見えていた。生成APIへの送信を記録し、トークン取得状況と分けて表示する。

- モデルごとの週間利用量。プロバイダーが返すトークン数がある場合はその値を集計し、ない場合は「週 N リクエスト」と「トークン数未取得」を表示する。
- 部分取得は「tokens（取得分）」と取得した回数/全呼び出し回数を併記。不完全な入力・出力の内訳は表示しない。記録なしと、本当に0 tokensと報告された応答も区別する。
- 各HTTP生成リクエストの送信前に1件記録する。スキーマ互換性の再試行も各1件、通信失敗も1件。カタログ・認証・使用量表示の問い合わせは数えない。通信前に権限で止めた生成は数えない。実際にプロバイダーへ到達したか、課金されたかは回数だけでは確定できない。
- プロバイダー側の記録済みフラグを通常/ストリームの上位集計へ伝え、二重計上を防ぐ。フォールバック先は実際に使ったモデルIDへ記録する。
- プロバイダーの独自トークン内訳も正規化。Googleのthoughts/tool-use、Anthropicのキャッシュ入力を含める。OpenAIのreasoningはcompletion/outputの内訳なので重ねて足さない。総数のみの応答にも対応する。推測でトークンや料金・契約残量へ換算しない。
- 既存DBへの列追加で移行。取得済みの過去トークン・リセット時刻を残す。未記録だった過去のリクエスト数は復元しない。以前からある既知の生成記録は各1回として残る。
- リセットは選択モデルだけを既存の時刻で区切る。モデルピッカーを開いた直後に更新し、開いている間の既存の定期更新も維持。
- DBへ保存するのはモデルID、数値、状態、時刻と許可済みレート制限ヘッダーだけ。プロンプトや資格情報は利用量記録に含めない。

応答フィールドの根拠:

- [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create): prompt_tokens / completion_tokens / total_tokens。
- [Google GenerateContent UsageMetadata](https://ai.google.dev/api/generate-content): promptTokenCount / candidatesTokenCount / thoughtsTokenCount / toolUsePromptTokenCount / totalTokenCount。
- [Anthropic prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching): input_tokensとは別のcache_creation_input_tokens / cache_read_input_tokens。

検証:

- 利用量・プロバイダー集計・通常/ストリームAPI・フォールバックの関連20テスト成功。移行、再起動、重複、部分/総数のみ/ゼロ/不正値、未取得、再試行、失敗、権限拒否、個別リセットを含む。
- UI/OAuthの21テストとproduction build成功。
- モックAPIのChromeで1180px/390px幅の表示・再取得・個別リセットを確認。実キー、実API、ユーザーDBは利用しない。Tauri実機やプロバイダー請求額との照合は未実施。
- 広い回帰スイートは54件中51件成功。今回変更していない既存の期待値3件（削除済みvision_fallbackロール、vision+completionモデルの一覧、旧OrnithのMLXへの自動移行）が現在の実装・環境と不整合で失敗。今回の利用量追加に合わせてこれらのモデル選択動作は変更しない。
