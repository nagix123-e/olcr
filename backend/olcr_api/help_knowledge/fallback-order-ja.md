# アカウントとモデルのフォールバックの違い

最初に、選択中の同じモデルを同一プロバイダー内のアカウント優先順で試します。すべて利用できない場合は設定した代替モデルへ進みます。
アカウントの順序は「接続先」→「アカウントと優先順位」の↑↓、モデルの順序はモデル設定のフォールバックで指定します。
モデル変更時に、既に登録した一時的に利用不可のフォールバックを勝手に消しません。別の外部モデルに切り替わる場合、その接続先へリクエストが送られます。

呼び出し前に利用可能・利用不可・不明を判定します。認証なし、再認証が必要、外部アクセスがオフ、ローカル実行環境・モデルが未導入、直前の上限・アクセス拒否が確認済みの場合は、呼び出さずに次の利用可能な候補へ進みます。不明な状態では通常の呼び出しで確認し、確認用の生成はしません。
上限の解除時刻やRetry-Afterが分かる場合はそこまで待ちます。時刻が不明な上限は短い待機、通信障害は短時間の待機として保存し、期限後に再試行できます。再接続・認証情報更新・接続設定の再登録で古い失敗記録を解除します。入力・画像・JSON形式に固有の400エラーではモデル全体を利用不可にしません。スキップ理由と再試行可能時刻は思考ログのOLCR処理状況に表示します。
