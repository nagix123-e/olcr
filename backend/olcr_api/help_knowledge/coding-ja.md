# コーディングと再開

作業フォルダーを指定し、「このアプリを実装して」「このファイルを修正して」のように成果物と変更内容を依頼します。
コーディングオーケストレーターのカードに計画、工程、変更・実行結果、検証結果を表示します。
カードを閉じてもタスクの記録は保存されます。同じ会話で「再開」と送ると、保存済みの状態から続行します。
追加・修正指示は同じ会話で具体的に伝えます。必要な確認や権限の承認が残っている場合は、その確認を済ませます。
失敗時は未完了工程と失敗理由を確認します。ファイル作成や検証が未完了なら完成したとは扱いません。

設定で「コーディングサブエージェント」を明示的にONにできます。Coding Orchestratorとは独立した設定で、初期状態はOFFです。ONにしてもサブエージェントは自動起動しません。重く、実装工程を互いに独立した書込範囲へ分割できるCoding Taskに限り、ユーザーのタスクへの明示指示、または通常の計画承認とは別のタスク専用承認がある場合だけ起動します。小さいタスク、依存関係がある工程、書込範囲が重なる場合は単独で実装します。

サブエージェントは現在のCoding Task実装モデルを共有します。Brainを一本化している場合は同じモデルを使い、別モデルへの切替やフォールバックはしません。ローカルモデルは推奨しません。役割遵守と結果統合の品質、応答時間、メモリ・計算負荷に影響します。workerは割当範囲内の変更案を返し、OLCRが状態と範囲を検証して直列適用します。親Taskは通常どおりレビューと検証を続け、リリース・公開作業にはworkerを使いません。進捗カードから個別承認または辞退ができ、Taskの一時停止や設定OFFは実行中workerも停止します。
